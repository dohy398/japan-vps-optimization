## 三网优化日本VPS里的"优化"，具体优化的是哪三段路

优化的是回程路由。这一点值得先讲清楚，因为它决定了你花的钱到底买到了什么。

中国电信、联通、移动三家的国际出口质量差异很大。默认情况下，境外服务器的回程流量会被丢进普通 transit 或 163 公众网，晚高峰拥堵、抖动、丢包一起上来。三网优化的做法是让三家各自的回程分别走自己的优质骨干：

- **电信**：CN2 GIA（AS4809），电信下一代承载网，绕开 163 公众网的拥堵段
- **联通**：AS9929，联通精品骨干，和默认的 AS4837 在国际高峰时段差距明显
- **移动**：CMI / CMIN2（AS58453），移动的国际优化出口，替代传统拥塞的普通 CMI 路径

GoMami 官方文档的表述是 "Triple-Network Direct — China Telecom CN2, Unicom AS9929, Mobile CMI direct lines"，并强调按源 IP 自动选路，多上游冗余加自动故障切换。第三方资料则普遍把移动侧写成 CMIN2（AS58453）。两套说法指的是同一件事，看测评时不用纠结字面差异。

官方给出的节点延迟口径是：香港 < 30ms、日本（东京）< 50ms、新加坡 < 70ms，并注明这是典型测量值，实际受本地 ISP、时段和网络状况影响。日本节点在这个表里的定位很明确——物理距离仅次于香港，价格比香港低一截，适合面向华北用户或者需要在日本有个落地点的场景。

深圳电信（本地 500Mbps）到这台机器，单线程跑到 404–417 Mbits/sec，基本贴着本地带宽上限。济南联通（本地 500Mbps）两轮分别在 541–545 和 358–359 Mbits/sec，也在本地线路上限附近。

移动的表现需要拆开看。广东移动（本地 1Gbps）上行多次出现 0 Mbits/sec 的断点，10 秒平均只有 37.6 Mbits/sec，但下行单线程能到 174 Mbits/sec。武汉移动上行约 46.3 Mbits/sec、下行约 433 Mbits/sec；宁波移动上行约 36.9 Mbits/sec、下行约 568 Mbits/sec。上行被 QoS 压得比较狠，下行正常。

## 三个常被写错或漏掉的地方

这一节讲三件在下单前容易被忽略、但会实际影响使用的事：超出流量后的限速方式、DDoS 防护的真实覆盖范围，以及 24 小时退款窗口该怎么用。竞品测评文章通常只提前两条，第三条几乎没人写。

### 超出流量不是断网，但基本等于站点不可用

官方 FAQ 的原文是"超出月配额后带宽可能被限速，具体策略取决于产品规格"，流量额度在每个计费周期重置。多个第三方资料给出的具体口径是限速到 20 KB/s 直到下个周期，不收超量费用。

20 KB/s 是什么概念：服务器还在线，SSH 连得上，ping 得通，但一个正常网页打开要等到天荒地老。对建站业务来说，这比直接停机更难受，因为你不会第一时间收到告警，等发现的时候流量早就用完了。

选套餐时流量要留余量。500GB 的 Nano 跑个人代理够用，挂图床或做视频中转就不够了。官方提供了自助购买流量包的功能，不用升级整档套餐，这个比硬扛到限速再处理要主动。

### 600 Gbps DDoS 是付费附加项，默认只有 best-effort

官网首页写的是 "up to 600 Gbps mitigation capacity"，读起来像全系标配。官方文档写得更细：

- 所有实例默认提供 **best-effort** 防护，自动检测清洗，正常流量不受影响
- 当攻击影响到其他客户时，IP 会被黑洞 **30–60 分钟**，自动释放，无法人工干预
- **600 Gbps 高级清洗是付费附加项**

这个区别对做游戏服、容易招惹攻击的业务很重要。默认防护能挡住小规模攻击，但真被人盯上了，黑洞 30 分钟起步是躲不掉的，而且客服也没法提前解封。需要更强防护的话得单独买附加服务，别按首页的宣传语做预期。
